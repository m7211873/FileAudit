# IP监控2.1 · 网络连接监控（NetWatcher）

> 项目代号：**IP监控2.1**（在 IP监控2.0 基础上做的小规模迭代修复版）
> 当前版本：**2.1.1（定版，2026-10-31）** —— 在 2.1.0 的 P0/P1 修复之上，修复了**托盘图标重复/幽灵图标**问题，并新增 `--quit` 优雅退出。
> （P0 29/29、P1 38/38、P1 后 P0 复跑 29/29，0 FAIL/0 WARN）；详见 [CHANGELOG.md](CHANGELOG.md)。
> 2.0 的交付物保持在 Gitee 仓库根目录不动；2.1 是与其**并列的新文件夹** `2.1/`。

一个在 Windows 上运行的**常驻后台**网络连接监控工具，图形化界面，记录电脑每次连接了哪些 IP、收发多少数据、连接了多久，并自动识别 IP 归属地（精确到城市）。

- **零依赖、零安装**：纯 C# 编写，用 Windows 自带的 .NET Framework 编译器编译成单个 `NetWatcher.exe`，双击即可运行。
- 数据按**日期**归档，可查看今天 / 昨天 / 前天或任意一天；旧版 1.0 的数据文件可以直接读取。
- **诚实标注**：普通权限下逐 IP 流量是「估算」，管理员权限下 EStats 可用才是「精确」，界面上明确区分。

> **2.1 是什么**：2.0 的核心能力（四标签页、原子写盘、诚实降级、托盘自启）全部保留；2.1 把 2.0 里"不够好"的地方修到可用，并已定版：
> **P0**——同日重启丢当天数据、`--selftest` 覆盖当天数据、`--selftest` 篡改开机自启、同一数据目录可能被多个实例同时写；
> **P1**——自启状态对账、启动最小化生效、管理员重启保留 `--datadir`、归属地开关即时生效、1.0 旧数据不再假精确、
> 精确模式 tooltip 说明仅 IPv4 TCP、非实时页刷新节流、EStats 首错写日志且恢复后清除错误。
> 按用户原话："版本迭代就是把不够好的地方一点点修到可用。"
>
> **2.1 的命名与位置**（与 2.0 并列、互不覆盖）：
>
> | 项 | 2.0 | 2.1 |
> |---|---|---|
> | 程序名 | IP监控2.0 | **IP监控2.1** |

> **升级前必须先在 2.0 里退出**：2.1 与 2.0 共用数据目录，2.1 的"同一数据目录单写实例"锁只约束 2.1 自己（详见 §2.6、§四）。

## 一、功能特性

| 功能 | 说明 |
|------|------|
| 连接记录 | 定时（默认 2 秒，可调 1~60 秒）扫描 TCP 连接（IPv4 + IPv6）：记录**所有有远端地址的连接状态**（ESTABLISHED、SYN_SENT、FIN_WAIT1/2、TIME_WAIT、CLOSE_WAIT 等，只排除 LISTEN），口径更接近 Windows 资源监视器；字节统计只对 ESTABLISHED 做差分（其它状态不产生字节）。**UDP/QUIC 无法逐 IP 归因**；采样是离散的，短于采样间隔的连接仍可能漏掉——想更全可调到 1 秒 |
| 实时视图 | 每 1 秒刷新：整机上下行速度、今日累计；上表按 IP 汇总，下表列出每条连接的明细 |
| 进程视图 | 资源监视器式**树形图**：应用程序 → PID → 远端 IP（含端口/协议/字节），按活跃度排序；支持双击 IP 行筛选 |
| 流量统计 | 每个 IP / 每个进程的累计下载、上传字节、平均速率、峰值速率 |
| 精确 / 估算标注 | 管理员且 EStats 可用时逐 IP 字节为**精确**，否则按连接数均分为**估算**，界面分别标注；**精确只覆盖 IPv4 TCP**（悬浮提示说明，IPv6/UDP 只计入总流量） |
| 连接时长与会话 | 每个 IP 的累计连接时长、**真实会话数**（由「无连接」变「有连接」的次数）、首次/最近连接时间 |
| 进程信息 | 进程名、完整路径、PID、进程启动时间（避免 PID 复用被合并统计） |
| IP 归属地 | 识别到**城市**级（国家 + 省市 + 城市 + 运营商），后台异步解析并本地缓存，不阻塞界面 |
| 总流量 | 整机累计上行/下行字节、实时上下行速率、当日峰值；统计时排除 Loopback / Tunnel 网卡，与逐 IP 口径一致 |
| 新 IP 标记 | 当天首次出现的公网 IP 用 `NEW` 标记/颜色提示，可选托盘气泡提醒 |
| 排序与复制 | 点击列头切换升/降序（刷新后保持）；表格行可 `Ctrl+C` 或右键复制 |
| 按日查看 | 今天 / 昨天 / 前天 + 日历选择任意日期；顶部搜索框按 IP / 进程 / 城市 / 域名过滤 |
| 历史概览 | 各日期的总流量、峰值、IP 数、采样次数汇总对比 |
| 导出 CSV | 把某一天的统计导出为 CSV（Excel 可直接打开） |
| 数据可靠性 | 每日 JSON **原子写盘**（临时文件带进程 PID 后缀再替换），最多保留每分钟一条采样曲线（1440 条/天）；**同一数据目录只允许一个写入实例** |
| 同日重启不丢数据 | **2.1 P0 修复**：程序重启时加载当天已有 JSON 并继续累加，不再把重启前当天的数据当空白重写 |
| 旧数据诚实降级 | **2.1 P1-9**：读到 1.0 时期"标记精确但逐 IP 字节全 0"的数据时自动降级为估算，不再假精确 |
| 兼容旧数据 | 能读取 1.0 的 `data\*.json`（缺失字段取默认值），升级不丢历史 |
| 启动最小化生效 | **2.1 P1-6**：勾选后开机自启/后台启动只驻留托盘；`--show` 可强制显示窗口 |
| 自启状态对账 | **2.1 P1-5**：打开设置前读取 HKCU 实际自启状态，保存后回读校准，避免误显示/误删 |
| 归属地开关即时生效 | **2.1 P1-8**：设置里关闭「IP 归属地识别」后立即停止联网查询，无需重启 |
| 刷新节流 | **2.1 P1-11**：进程视图/按日统计每 ≥5 秒、历史概览每 ≥15 秒才重建表格（实时页仍每次采样刷新） |
| 后台常驻 | 关闭窗口最小化到系统托盘，监控继续运行；单实例：重复启动**不会弹「已经在运行」**，而是直接**唤出已有实例的窗口**（`--show` 同义）；若已有实例卡死，程序会提示到任务管理器结束 `NetWatcher.exe` |
| 托盘图标（2.1.1 修复） | 启动后只补偿/重建一次托盘图标，退出先停定时器再释放图标；不会再因反复 hide/show 或退出竞态产生"重复/幽灵图标"。可用 `--quit` 优雅停止程序 |
| 开机自启 | 写入 HKCU 启动项（2.1 的值名是 `NetWatcher2.1`），登录后在后台运行（不需要管理员） |

## 二、使用方法

### 2.1 启动

- 双击 `2.1\bin\NetWatcher.exe`，或双击桌面快捷方式「IP监控2.1」；
- 也可以运行 `2.1\install.ps1`（见 §2.6），安装脚本会创建桌面快捷方式并注册开机自启。

启动后主窗口顶部依次是：标题、**运行模式**（精确/估算，带颜色）、最近扫描时间、扫描间隔。

日期行：`今天 / 昨天 / 前天` 三个按钮 + 日历选择框 + **搜索框**（输入 IP、进程名、城市或域名过滤）+ 刷新按钮。

> 主窗口标题 / 设置窗口标题里的版本号由程序维护（`2.1\src\AssemblyInfo.cs` 的 `AssemblyVersion=2.1.1.0`）；2.1 的截图见 `docs/screenshots/`（**当前沿用 2.0 真机截图**，界面布局一致，标题与部分文案以 2.1 实际运行为准）。

### 2.2 四个标签页

| 标签页 | 内容 |
|--------|------|
| **实时连接** | 顶部 4 个统计（↓速度 / ↑速度 / 今日↓ / 今日↑）；上表按 IP 汇总（IP、城市/地区、运营商、连接数、↓速度、↑速度、标记）；下表是连接明细（IP、地址、应用程序、PID、端口、协议、上传、下载、总流量、时长、标记） |
| **进程视图** | 树形「应用程序 → PID → 远端 IP:端口(协议)」，每个节点显示收发字节与连接次数；同一进程的不同启动实例按 PID + 启动时间区分；双击某个 IP 行可跳回筛选结果 |
| **按日统计** | 所选日期的逐 IP 明细：城市、运营商、连接时长、会话数、下载/上传字节、平均/峰值速率、是否精确 |
| **历史概览** | 各日期的总流量、峰值、IP 数、采样次数对比 |

### 2.3 排序、复制、筛选

- 点击任意表格的**列头**排序，再次点击切换升/降序；切换标签页或刷新后排序方式保持。
- 选中行按 `Ctrl+C`，或右键菜单「复制」，把整行文本复制到剪贴板。
- 顶部搜索框的内容会同时过滤表格；清空后恢复。

### 2.4 托盘与关闭窗口

- 关闭主窗口 = **最小化到系统托盘**（右下角图标），监控继续。
- 托盘图标右键：显示主窗口 / 刷新 / 退出。
- 当天首次出现新的公网 IP 时，可弹出托盘气泡提醒（设置里可关）。
- 开机自启写入 HKCU Run（2.1 值名 `NetWatcher2.1`）后用 `--background` 启动。如果**资源管理器重启**（任务栏重建 / `TaskbarCreated` 消息）或你再次双击程序，程序会自动补回托盘图标；若托盘图标实在看不到，**直接再双击一次程序**即可唤出已有实例的窗口（不会重复启动第二个进程）。

### 2.5 设置

点击底部「设置」可修改：

| 设置项 | 说明 |
|--------|------|
| 扫描间隔 | **1 秒（最精细）/ 2 秒（推荐，默认）/ 5 秒 / 10 秒 / 30 秒 / 60 秒（最省资源）**；越短越精细，占用略高 |
| 开机自动启动 | 等价于 `--autostart-on/off`，写 HKCU 启动项（2.1 值名 `NetWatcher2.1`）；**打开设置时会先读取注册表实际状态对账**（P1-5） |
| 数据保留天数 | 0 = 永久保留；大于 0 时自动清理超过天数的旧数据 |
| IP 归属地识别 | 关闭后**立即**停止联网查询城市信息（P1-8，无需重启） |
| 新 IP 提示 | 新公网 IP 首次出现时是否弹托盘气泡 |
| 显示本机/内网 IP | 是否在列表中显示 127.x / 10.x / 192.168.x 等本地地址 |
| 启动时最小化 | 开机自启/后台启动时只驻留托盘，不弹主窗口（**P1-6 已生效**；`--show` 可强制显示） |

底部还有：**导出CSV**、**打开数据目录**、**以管理员身份重启**（用于切换到精确模式）。
以管理员身份重启时会保留当前 `--datadir`（P1-7）。

### 2.6 安装、升级与卸载（推荐）

`2.1/` 目录提供两个 PowerShell 脚本（Windows 自带组件，无需安装任何东西）：

```powershell
# 安装（在 2.1 目录里执行）：复制程序到 %LOCALAPPDATA%\Programs\NetWatcher2.1
#   + 数据目录（%APPDATA%\NetWatcher，与 2.0 共用）+ 开机自启（值名 NetWatcher2.1）
#   + 桌面「IP监控2.1」快捷方式
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1

# 可选参数
#   -NoShortcut            不创建桌面快捷方式
#   -Portable              绿色模式：不复制程序，原地运行（快捷方式/自启指向 2.1\bin 目录）
#   -DataDir "D:\NetWatcherData"   使用自定义数据目录

# 卸载（在 2.1 目录里执行）：结束 2.1 进程 + 删除 2.1 开机自启 + 删除「IP监控2.1」快捷方式
#   + 删除 2.1 安装目录（默认保留数据）
powershell -NoProfile -ExecutionPolicy Bypass -File uninstall.ps1

# 可选参数
#   -KeepBinary            保留 %LOCALAPPDATA%\Programs\NetWatcher2.1 下的程序文件
#   -DeleteData            连同数据目录一起删除（谨慎！2.1 与 2.0 共用，2.0 的历史也会没）
```

两个脚本都可以**重复执行**（幂等）；安装/卸载都不需要管理员权限。

> 2.1 的安装/卸载脚本已通过 **Windows PowerShell 5.1 Parser 校验（0 语法错误）**，并已于 **2026-10-31 真机完成安装/卸载验收**
> （install → 启动/数据续接 → uninstall 保留数据 → 重装；升级前仍请先退出 2.0，见下）。

**2.1 与 2.0 的边界（脚本刻意保证）**：

- 2.1 的安装/卸载只操作**自己的**：`%LOCALAPPDATA%\Programs\NetWatcher2.1`、`HKCU\...\Run\NetWatcher2.1`、桌面 `IP监控2.1.lnk`；
- **绝不**删除或改写 2.0 的 `IP监控.lnk`、`Run\NetWatcher`、`%LOCALAPPDATA%\Programs\NetWatcher`、`%APPDATA%\NetWatcher` 数据（除非你显式 `-DeleteData`，且脚本会二次警告）；
- 若 2.0 的开机自启项还在，安装脚本会**只读提示**你（不会替你删）；要停用 2.0 请运行 2.0 自己的 `uninstall.ps1`（默认保留数据）；
- 桌面上同时存在「IP监控」（2.0）和「IP监控2.1」是预期行为。

**从 2.0 升级到 2.1 的步骤**：

1. 先在 2.0 托盘右键 → **退出**（或任务管理器结束 2.0 的 `NetWatcher.exe`），确保没有 2.0 实例在写数据；
2. 在 `2.1\` 目录运行 `install.ps1`；
3. 双击桌面「IP监控2.1」启动（数据目录不变，历史自动接续）；
4. 2.0 的文件/快捷方式/自启值不会被删；确认 2.1 正常后，如需彻底停用 2.0，运行 2.0 的 `uninstall.ps1`（**不要**加 `-DeleteData`，数据是共用的）。

> 注意：如果用 `-DataDir` 指定了自定义数据目录，卸载时也要带上同样的 `-DataDir`，`-DeleteData` 才会删除那个目录。
> 注意：**不要同时运行 2.0 与 2.1**。2.1 的写锁（`NetWatcher2.1_DataLock_<数据目录哈希>`）只在一个 2.1 进程内生效，管不到 2.0；两个版本同时写同一数据目录会互相覆盖。

## 三、管理员精确模式与 EStats 限制

### 3.1 两种模式

| 模式 | 条件 | 逐 IP 字节来源 | 界面标注（三种文案） |
|---|---|---|---|
| **精确** | 以管理员身份运行 **且** 至少有一条连接成功读到 EStats | `GetPerTcpConnectionEStats` 逐连接读取、按采样间隔求差分 | `运行模式：逐IP精确（管理员）`（绿色） |
| **估算（管理员）** | 管理员运行，但本次采样无 EStats 数据 | 按 ESTABLISHED TCP 连接数均分整机总流量 | `运行模式：逐IP估算（管理员，本次采样无 EStats 数据）`（橙色） |
| **估算（普通）** | 普通权限 | 按 ESTABLISHED TCP 连接数均分整机总流量 | `运行模式：逐IP估算（非管理员）`（橙色） |

- **判据**：只有**确实有一条连接成功读到 EStats** 才显示「精确」。这是对 1.0 bug 的修正——1.0 会无条件标记 `precise=true`，EStats 失败被静默吞掉，造成「逐 IP 字节恒为 0 却显示精确」；2.0/2.1 按实际返回值判断，失败时显示**橙色「逐IP估算」**，鼠标悬停可看到最近一次失败原因（`LastEStatsError`）。
- EStats 失败时：状态栏显示红色错误、运行模式悬浮提示里有诊断信息（**2.1 P1-12：首次失败会写 `monitor.log`，精确模式恢复后自动清除该错误**）；要完整的参数矩阵诊断
  （`rw=1/4 × rod=48/16/1024` 各组合的 rc/winerr），请以管理员身份运行 `--selftest`，
  看 `selftest.log` 里的 `EStats 结论:` 行。`monitor.log` 只记录采样/写盘异常。
- **EStats 在部分机器/系统上可能不可用**：非管理员通常返回 `ERROR_NOT_SUPPORTED (50)`；管理员也可能失败，返回 `ERROR_NOT_SUPPORTED (50)` / `ERROR_INVALID_USER_BUFFER (1784)`（例如装有网络加速器、LSP/WFP 过滤驱动的环境）。以管理员身份运行 `NetWatcher.exe --selftest`，看 `selftest.log` 里的 `EStats 结论:` 一行即可确认本机是否支持；不可用时程序自动退回「估算」，**不会谎报精确**。

### 3.2 为什么普通权限拿不到逐 IP 精确字节

Windows 出于安全考虑，读取「其它进程/连接」的逐连接字节数需要管理员权限：普通权限调用 EStats 会返回 `ERROR_NOT_SUPPORTED`（错误码 50）。即使以管理员运行，在装有网络加速器 / LSP / WFP 过滤驱动的机器上也可能失败（错误码 50 或 1784），此时程序只能按连接数估算——**这是系统级限制，不是程序缺陷**。

### 3.3 UDP / QUIC 无法逐 IP 归因

Windows 的 TCP 连接表能列出远端的 TCP 连接；而 **UDP 是无连接协议，系统接口不提供 UDP 的远端 IP**，所以：

- UDP 流量（包括基于 UDP 的 **QUIC / HTTP/3**）**无法归因到具体远端 IP**；
- 它**仍然计入整机总流量**，但不会出现在逐 IP / 逐进程的字节统计里；
- 因此当机器上有较多 QUIC 流量时，「逐 IP 字节之和」会**小于**「整机总流量」，这是正常现象。

### 3.4 如何切换到精确模式

- 右键桌面快捷方式「IP监控2.1」→ **以管理员身份运行**；或
- 在程序底部点「以管理员身份重启」。

切换后看窗口顶部的运行模式标注（精确=绿色，估算=橙色）；估算时把鼠标停在标注上可看到 `LastEStatsError`（最近一次 EStats 失败原因）。想确认本机能不能精确，以管理员身份运行 `NetWatcher.exe --selftest`，看 `selftest.log` 里的 `EStats 结论: 可用/不可用(原因)`。

## 四、数据存储

数据目录默认 `%APPDATA%\NetWatcher\`（**2.1 与 2.0 共用，升级不迁移**）：

| 文件 / 目录 | 内容 |
|---|---|
| `data\YYYY-MM-DD.json` | 每天的统计（JSON，可直接查看）；含总流量、逐 IP、逐进程、采样曲线 |
| `config.json` | 配置（扫描间隔、保留天数、归属地开关等） |
| `geocache.json` | IP 归属地缓存 |
| `monitor.log` | 运行日志（采样/写盘异常；EStats 诊断见 `selftest.log`） |
| `startup.log` | 启动阶段时间线（用于排查"进程在但没界面 / 没采集"） |
| `crash.log` | 未处理异常导致的崩溃日志（排查用） |
| `ui-error.log` | 界面/UI 线程异常日志（排查用） |
| `selftest.log` | `--selftest` 自检输出（2.1 起自检对 `data\` 只读、不改自启；仍会写 `selftest.log`、`selftest-store\` 临时测试目录（用后删除）与 GeoIP 缓存 `geocache.json`） |
| `daemon.log` | `--daemon` 无界面采集的退出汇总 |

**单写实例（2.1 新增）**：

- 同一数据目录同一时间只允许**一个 2.1 写入实例**。GUI 与 `--daemon` 启动时都会抢一个按数据目录命名的锁：
  `NetWatcher2.1_DataLock_<MD5(数据目录绝对路径小写)>`；
- `--daemon` 抢不到锁 → 直接**退出码 2**（便于脚本判断"已有实例在用这个目录"）；
- GUI 抢不到锁 → 提示"该数据目录已被另一个实例占用"后退出，不会两个窗口同时写；
- `--selftest` **只读**，不抢锁、不写当天数据文件；`--mutex-tag` 只改单实例互斥量名字，**不影响**数据写锁（同一数据目录永远只能一个写入实例）；
- 测试/截图请用**绝对路径的 `--datadir` 临时目录**，不要指向 `%APPDATA%\NetWatcher`。

其它：

- 写盘是**原子**的：先写临时文件，再用替换/移动覆盖正式文件，避免断电或崩溃产生半个文件；
  2.1 起临时文件名为 `<文件名>.<进程PID>.tmp`，并发或上次崩溃残留不会互相覆盖。
- **1.0 旧数据的"假精确"会被降级**（P1-9）：1.0 会把 `bytesPrecise` 无条件写成 true 而逐 IP 字节全 0；
  2.1 读到这类数据时自动改为估算显示，不再沿用错误标记。
- 采样的分钟曲线每天最多 1440 条；写盘有节流（默认至少间隔 15 秒，跨日或退出时强制写）。
- 用 `--datadir <路径>` 可指定其它数据目录（见下一节）；安装脚本的 `-DataDir` 会把该参数写进开机自启命令。
- 数据只保存在本机；卸载默认保留数据，只有 `uninstall.ps1 -DeleteData` 才删除（2.1 会二次警告：2.0 的历史也会一起删）。

## 五、命令行参数

| 参数 | 作用 |
|------|------|
| （无参数） | 启动图形界面 |
| `--background` / `-b` / `--minimized` | 后台启动（只驻留托盘，不显示主窗口，用于开机自启；资源管理器重启或再次启动时会自动补回托盘图标） |
| `--show` | 若已有实例在运行，**唤出它的主窗口**（重复双击程序等同此行为）；不会重复启动第二个进程 |
| `--selftest` / `--test` | 运行自检，诊断写入数据目录下的 `selftest.log`（**2.1 起对 `data\` 只读、不改 HKCU 自启项**；仍会写 `selftest.log`、`selftest-store\` 临时测试目录与 GeoIP 缓存） |
| `--daemon <秒>` | 无界面采集指定秒数后退出（便于测试/纯后台采集）；数据目录写锁被占用时**退出码 2** |
| `--mutex-tag <标签>` | 给**单实例互斥量**加标签（`NetWatcher2.1_SingleInstance_Mutex_<标签>`），便于在同一台机器上同时运行多个**测试**实例；常规使用不需要，且**不影响数据写锁** |
| `--quit` / `--exit` | 请求**已运行的实例优雅退出**（保存数据、移除托盘图标、正常结束）；没有实例时返回退出码 1。适合脚本/自动化停止程序，避免强杀留下幽灵托盘图标 |
| `--datadir <路径>` | 指定数据目录（2.1 的写锁按此路径计算，不同目录可并行） |
| `--autostart-on` / `--autostart-off` | 命令行开启/关闭开机自启（写 HKCU 启动项 `NetWatcher2.1`，不需要管理员） |

补充说明：

- **单实例命名（2.1）**：互斥量 `NetWatcher2.1_SingleInstance_Mutex`，唤出事件 `NetWatcher2.1_SingleInstance_Mutex_Activate`；加 `--mutex-tag X` 时两者都追加 `_X`。与 2.0 的 `NetWatcher_SingleInstance_Mutex` 不同名，所以 2.0 与 2.1 可以各自有一个实例同时存在——但**共用数据目录，不要同时运行**。
- `--show`：单实例唤出。已有实例在运行时再次启动（或双击程序）会唤出已有窗口而不是再开一个进程；如果已有实例卡死，会提示到任务管理器结束 `NetWatcher.exe` 后再启动。
- `--daemon <秒>`：无界面采集指定秒数后自动退出，退出时在数据目录写 `daemon.log` 汇总（采样数、总流量、IP/进程数、是否精确），用于测试或纯后台采集。
- 诊断日志：启动阶段时间线写入 `<数据目录>\startup.log`；未处理异常写入 `<数据目录>\crash.log`；界面/UI 线程异常写入 `<数据目录>\ui-error.log`（`<数据目录>` 为 `--datadir` 指定目录，未指定则 `%APPDATA%\NetWatcher`），用于排查"静默退出 / 进程在但没界面"。

### 自检说明（`--selftest`，2.1 行为）

自检会把诊断写到 `<数据目录>\selftest.log`，包括：

- 管理员状态、进程位数、操作系统版本；
- 网卡统计（每个网卡的名字与收发字节，并标明 Loopback / Tunnel 是否被排除）；
- TCP 连接总数 / ESTABLISHED 数 / 远端连接数（前 15 条）；
- **EStats 诊断**：对前几条连接尝试 `rw=1/4 × rod=48/16/1024` 六种组合，逐条打印 `rc/winerr`，并重读确认字节增长——这是判断管理员精确模式能否工作的唯一依据；
- GeoIP 查询、存储读写、开机自启注册表、目录列表；
- 结论行：`EStats 结论: 可用/不可用(原因)`。

**2.1 的两条硬约束**（2.0 的坑）：

1. 自检**对 `data\` 只读**：不再创建/覆盖 `data\<今天>.json`（2.0 曾因此把用户当天的真实数据覆盖成自检样本）；
   存储读写测试在 `<datadir>\selftest-store\` 临时子目录进行，用后删除；
2. 自检**不再写 HKCU 自启项**：2.0 的自检会试着写/删 `Run\NetWatcher`，可能篡改用户的开机自启；
   2.1 只对真实值做只读检查，注册表往返测试改用临时值名 `NetWatcher2.1_SelfTest_<PID>`。

> 所以自检不是"完全不写盘"：它仍会在 `<数据目录>` 写 `selftest.log` 与一次 GeoIP 查询的 `geocache.json` 缓存。

普通权限下自检仍会尝试 EStats，但结论会是「不可用（当前非管理员，需以管理员身份运行）」；想验证精确模式请以管理员身份运行自检。

## 七、技术说明与限制

- **技术栈**：C#（C# 5 语法）/ .NET Framework 4.8 / WinForms，P/Invoke 调用 `iphlpapi.dll`（`GetExtendedTcpTable`、`GetPerTcpConnectionEStats` 等）。
- **连接枚举**：TCP 连接（含 IPv6）普通权限即可枚举，含 PID、进程名、进程路径、进程启动时间；记录范围是**所有有远端地址的连接状态**（ESTABLISHED、SYN_SENT、FIN_WAIT1/2、TIME_WAIT、CLOSE_WAIT 等，只排除 LISTEN），与 Windows 资源监视器的口径更接近；字节只对 ESTABLISHED 做差分（其它状态不产生字节）。
- **采样是离散的**：扫描间隔内建立又关闭的短连接仍可能漏掉（默认 2 秒；想更全可在设置里调到 1 秒）。
- **刷新节流**（P1-11）：实时连接页每次采样刷新；进程视图 / 按日统计每 ≥5 秒、历史概览每 ≥15 秒才重建表格。
- **总流量口径**：整机累计收发只统计处于 Up 状态、且**排除 Loopback / Tunnel** 的网卡，避免与逐 IP 统计口径不一致。
- **逐 IP 字节**：管理员 + EStats 成功时为每个 TCP 连接的精确差分；否则为按连接数估算。估算值在数据里也标记为非精确。
- **精确只覆盖 IPv4 TCP**：IPv6 的 TCP 连接和所有 UDP/QUIC 流量只计入整机总流量，不进逐 IP 精确字节（运行模式 tooltip 已说明）。
- **UDP / QUIC**：系统不提供 UDP 远端 IP，无法逐 IP 归因；UDP 流量只计入整机总流量（见第三节）。
- **受保护进程**：个别系统/受保护进程可能读不到进程名或完整路径，界面显示为「(未知)」。
- **IP 归属地**：使用 `ip-api.com` 免费接口（中文城市名），首次遇到的新 IP 在后台异步解析并缓存，不阻塞监控；内网/本机地址自动识别为「本地/内网地址」，不发起联网查询。查询时**绕过系统代理**（程序硬编码 `Proxy = null`），避免某些机器上系统代理配置导致归属地查询超时。
- **逐 IP 精确流量的已知限制**：精确模式依赖 Windows `GetPerTcpConnectionEStats`。该接口在部分机器/系统上会失败，返回 `ERROR_NOT_SUPPORTED (50)` / `ERROR_INVALID_USER_BUFFER (1784)`（例如装有网络加速器、LSP/WFP 过滤驱动的环境；本仓库开发机实测即如此，换用 `ref struct + IntPtr`、`byte[]`、指针 row 三种封送方式结果一致，怀疑与 Steam++ Accelerator 之类的网络加速驱动有关）。此时程序自动降级为「估算」并在状态栏/tooltip 标注，**不会谎报精确**。用 `NetWatcher.exe --selftest`（**以管理员身份运行**）查看日志里的 `EStats 结论:` 一行即可确认本机是否支持；自检会打印 `rw=1/4 × rod=48/16/1024` 六种组合的 rc/winerr。
- **数据模型**：逐 IP 的 `sessionCount` 是真实会话数（由「无连接」变「有连接」的次数），`sampleCount` 是出现过的采样次数；逐进程的 `connCount` 是连接出现次数（每个连接只计一次），都不再随采样次数虚增。
- **已知限制**：估算模式下逐 IP 字节不能反映真实占比；Wi-Fi/虚拟网卡较多时网卡合计可能与运营商侧统计有差异；归属地数据库由第三方接口提供，城市可能不准确。

## 八、隐私

- 所有连接记录、进程信息、流量数据**只保存在本机**，程序不会主动上传任何记录。
- 唯一的联网行为是查询公网 IP 的归属地：只发送 IP 地址字符串（不含端口、进程、流量信息），结果缓存在本地。
- 关闭「IP 归属地识别」后，程序完全不发起任何网络查询（2.1 P1-8：设置保存后立即生效，无需重启）。
- 项目**没有**遥测、账号体系或云同步功能。
