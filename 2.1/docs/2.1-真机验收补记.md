> 本文件记录 2.1 定版后在**用户真实机器**上做的安装/卸载全链路验收，以及验收中发现并修复的

## 1. 启动顺序修正（P0-4 回归）

- **发现**：数据写锁（`NetWatcher2.1_DataLock_<MD5(datadir)>`）最初在 `Program.Main` 里先于
  「单实例唤出」判断抢锁。结果：2.1 已在运行时，用户**再次双击**（或 `--show`）会先弹
  “数据目录已被另一个实例占用”，而不是像 2.0 那样唤出已有窗口。
- **修正**：GUI 的数据写锁改为在**单实例唤出判断之后**才抢（`--daemon` 仍在启动早期抢锁，
  以确保 daemon 不会与 GUI 并发写；`--selftest` 只读、不抢）。因此：
  - 同一 `--mutex-tag` 的二次启动 → 唤出已有窗口，二次进程退出（不误报占用）；
  - 不同 `--mutex-tag` 抢同一 datadir → 才提示“数据目录已被占用”；
  - 二次启动等待窗口出现的最长时间从 1.5s 放宽到 5s（首个实例 UI 忙时更稳）。
- **回归**：新增 `tools/qa/regression-activation.ps1`（A1~E1 共 9 项），
  覆盖隐藏启动、`--show`/普通二次启动唤出、不同 tag 冲突、daemon exit=2、清理。
  **RESULT: PASS  PASS=9  FAIL=0**；修正后复跑 `regression-p0.ps1` **30/30**、
  `regression-p1.ps1` **38/38**，无回归。
