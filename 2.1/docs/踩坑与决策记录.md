## 一、环境与工具链

### 1.1 【最坑】从 agent 工作区目录运行的程序写不了 `%APPDATA%`

- **症状**：程序进程明明在运行、窗口/托盘时有时无，但**数据文件不更新**、IP 列表很少，
  重启后"像没自启"。看起来像托盘或监测 bug，实际是**写入失败**。
- **根因**：开发/运行环境把"从工作区目录启动的进程"限制为**只能写工作区**。
  同一个 exe：
  | exe 所在位置 | 写 `%APPDATA%\NetWatcher` |
  |---|---|
  | 工作区 `...\default-workspace\NetWatcher\bin\` | ❌ 失败 |
  | `%LOCALAPPDATA%\Programs\NetWatcher\` | ✅ 成功 |
  | `%TEMP%` | ✅ 成功 |
- **处理**：`install.ps1` 改为**先把 exe/app.ico 复制到 `%LOCALAPPDATA%\Programs\NetWatcher`**，
  快捷方式与 HKCU 自启都指向安装副本；`-Portable` 保留原地运行。
- **复现方法**：把同一个 exe 分别放到工作区与 `%TEMP%`，各自 `--selftest --datadir %APPDATA%\NetWatcherTest`
  比较是否生成 `selftest.log`。
- **教训**：任何"进程在但没数据"的问题，先验证**能不能写目标目录**，不要先怀疑代码逻辑。

### 1.2 Windows PowerShell 5.1 读中文脚本必须带 UTF-8 BOM

- **症状**：`powershell -File install.ps1` 报 `Unexpected token`/`ParserError`，同样的文件在编辑器里看完全正常。
- **根因**：UTF-8 **无 BOM** 的中文脚本会被 5.1 按本地代码页解释，引号/花括号被打乱 → 解析错误。
- **处理**：所有含中文的 `.ps1` 一律 `UTF8Encoding($true)` 写入（带 BOM）；
  或统一用 `pwsh` 7 执行。
- **检查**：`[System.Management.Automation.Language.Parser]::ParseFile($p,[ref]$null,[ref]$err)` 有错即失败。

### 1.3 从 agent shell 直接 `Start-Process` 启动 GUI exe 会让命令挂住

- **症状**：脚本执行到 `Start-Process NetWatcher.exe` 后永不返回；或整条工具调用超时。
- **根因**：子进程继承了 stdout 管道，GUI 常驻进程不退出，父进程/输出收集器等 EOF。
- **处理**：
  - 启动 GUI 用 `Invoke-CimMethod -ClassName Win32_Process -MethodName Create`（脱离 stdio）；
  - 或 `Start-Process -RedirectStandardOutput/-RedirectStandardError`（短命进程）；
  - 结束进程**按 PID**，不要按进程名批量杀（会误杀其它 agent/用户的实例）。
- **附带坑**：**WMI 启动的进程 `%TEMP%` 可能为空**，导致崩溃日志写不进去（表现为"静默退出"）。
  因此所有路径一律用绝对路径；崩溃日志改写数据目录（`crash.log`/`ui-error.log`）。

### 1.4 截图与自动化交互

- `CopyFromScreen` 只能截"屏幕可见区域"：**被其它窗口遮挡会截错**。
- `PrintWindow` 对 WinForms 窗口**返回失败**（本机实测），不要依赖它。
- 可用方案：`SetWindowPos(HWND_TOPMOST)` 把窗口置顶 → `CopyFromScreen` → 还原。
- **管理员窗口无法被非管理员程序模拟点击/按键**（UIPI）：UI 自动化请用非管理员实例，
  或改用带 `--mutex-tag` 的临时实例 + 临时数据目录做截图/验收。
- 判断"第二个实例是否唤出窗口"：用进程主窗口 `vis=True` + 窗口矩形（EnumWindows）验证，
  不要用 `Get-Process.MainWindowTitle`（隐藏窗口时为空）。用 `FindWindow` 按标题时注意**脚本编码**（见 1.2），
  中文标题字符串在无 BOM 脚本里会被打乱导致找不到窗口。

## 二、Windows 网络 API

### 2.1 `GetPerTcpConnectionEStats` 在部分机器上不可用（本机实测）

- **症状**：管理员模式下"精确流量"仍为 0；`--selftest` 打印 `set rc=50`、`get rc=1784`。
- **实测数据（必须记住）**：
  - 非管理员：`SetPerTcpConnectionEStats` → `rc=50 (ERROR_NOT_SUPPORTED)`，`GetPerTcpConnectionEStats` → `1784 (ERROR_INVALID_USER_BUFFER)`；
  - **管理员**（用户右键以管理员运行）：仍是 `rc=50`，`winerr=122 (ERROR_INSUFFICIENT_BUFFER)`；
  - 三种封送方式（`ref struct + IntPtr`、`byte[]`、指针 row）结果**完全一致**，排除 P/Invoke 封送问题；
  - 连不需要 enable 的 `TcpConnectionEstatsSynOpts`（type 0）都返回 1784。
- **猜测**：与机器上的网络过滤/加速驱动（本机装有 Steam++ Accelerator）或系统 TCP 栈配置有关。
- **处理**：程序**自动探测**参数组合，失败就诚实降级为「估算」，状态栏/tooltip 显示原因，**绝不含糊地标"精确"**。
  这比 1.0 的做法（无条件 `precise=true`）正确。
- **教训**：不要假设"API 存在 = 一定能用"；对能力型 API 必须**运行时探测 + 可观测的失败原因**。

### 2.2 UDP / QUIC 拿不到远端 IP

- `GetExtendedUdpTable` 只提供**本地端点**（LocalAddr/Port/PID），**没有远端地址**。
- 因此 QUIC/HTTP3、视频、游戏、DNS 等 UDP 流量：**只能计入整机总流量，无法归因到远端 IP**。
- 想要覆盖必须上 ETW（`Microsoft-Windows-Kernel-Network`，需要管理员 + 自写 ETW 消费者，工作量大）。
  不要把"UDP 逐 IP"写进承诺。
- 对称地：`GetExtendedTcpTable` 的 `TCP_TABLE_OWNER_PID_ALL` 有远端地址与 PID，普通权限即可用（≤ Win10）。

### 2.3 整机流量口径：必须排除 Loopback/Tunnel

- `NetworkInterface.GetIPStatistics()` 会包含 Loopback 与 VPN/Tunnel 虚拟网卡 → 与逐 IP 合计对不上、数值虚高。
- 处理：只统计 `OperationalStatus == Up` 且类型不是 `Loopback` / `Tunnel` 的网卡。

### 2.4 IP 归属地查询必须 `Proxy = null`

- **症状**：`GeoIP(8.8.8.8)` 永远 `error`，但 PowerShell `Invoke-WebRequest` 却成功。
- **根因**：本机系统代理配置指向不可用地址，`.NET HttpWebRequest` 默认走系统代理 → 超时。
- **处理**：`req.Proxy = null` 直连；超时 8 秒；后台异步解析 + 本地缓存（`geocache.json`），不阻塞监控。
- **注意**：`WebClient.DownloadString` 会按默认编码解码，中文会乱码；用 `HttpWebRequest` + `StreamReader(UTF8)`。

### 2.5 进程名/路径/启动时间

- `Process.GetProcesses()` / `Process.StartTime` 在受限环境下可能取不到（本机 agent 会话里只看到 9 个进程）；
  `Process.MainModule.FileName` 对受保护进程会抛异常。
- 处理：
  - 路径用 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `QueryFullProcessImageName`（多数进程可用）；
  - 启动时间用 `GetProcessTimes`（同一个 handle）；
  - **进程名兜底 = 从完整路径取文件名**（本机实测比 `Process.ProcessName` 更可靠）；
  - 进程聚合键用 `进程名|PID|启动时间`，避免 PID 复用被合并。

## 三、产品设计（1.0 的教训）

### 3.1 1.0 的核心缺陷（都有数据证据）

| 缺陷 | 证据 | 2.0 修法 |
|---|---|---|
| 逐 IP 字节恒为 0，却标"精确" | 两天真实数据 218 个 IP 全 0，当日总流量 276MB；代码里 `precise=true` 无条件赋值 | 按实际返回值判断 + 诚实降级 |
| 总流量含 Loopback/Tunnel | 与逐 IP 合计完全对不上 | 排除这两类网卡 |
| "连接次数"每采样累加 | Steam++.Accelerator 一个 PID 显示 585 次 | 真实新增连接数（按连接 key 去重） |
| 界面标签栏被遮挡 | 真机截图：4 个标签页只能看到"实时连接"；控件树显示 TabControl 被 Top Panel 覆盖 | `TableLayoutPanel` 三行布局，截图验收 |
| 无原子写、整天 JSON 重写 | 133KB/1.1 小时，随采样膨胀 | tmp → Replace 原子写 + 15s 节流 + 分钟桶 |
| 城市简繁混排 | "中国" vs "中華人民共和國"、"紐華克" | 统一归一化 |

### 3.2 WinForms 布局：不要在同一个容器里混用 `Dock.Fill` 与 `Dock.Top`

- 1.0 的 tab 页里 `Controls.Add(liveTop)` 之后再加 `Dock.Fill` 的 `SplitContainer`，层叠顺序导致
  **Top 面板被 Fill 面板覆盖/尺寸为 0**，用户看不到标签栏和列头。
- **规范**：根容器用 `TableLayoutPanel` 显式分行（header AutoSize / tabs 100% / footer AutoSize），
  页面内部同样用 TLP；不要靠 `Controls.Add` 顺序赌 Dock 布局。
- 验收方式：真机截图 + `EnumChildWindows` 导出控件矩形/可见性，而不是"看代码觉得对"。

### 3.3 单实例 + 托盘 + 开机自启：必须留"叫得出来"的路

- **事故**：开机自启的实例 `--background` 运行后没有托盘图标（通知区域未就绪时创建失败），
  用户再双击只得到"已经在运行"，**彻底没有入口**，只能任务管理器杀进程。
- **处理组合拳**：
  1. **引擎与界面解耦**：监控在 `Program.Main` 里先启动，UI 出问题不影响采集；
  2. **二次启动 = 唤起第一个实例窗口**（命名事件 `..._Activate` + `ShowMain`），
     若第一个实例无响应，弹可操作提示（任务管理器结束进程 + 日志路径）；
  3. **托盘自愈**：响应 `TaskbarCreated`、后台启动后 30 秒内每 3 秒重试、`--show` 别名；
  4. **启动时间线** `startup.log`：下次这类问题一眼定位（时间戳到毫秒）。

### 3.4 能力型功能要"可解释地降级"

- 精确模式不可用时：状态栏明确显示「逐IP估算（管理员，本次采样无 EStats 数据）」+ tooltip 显示 `rc/winerr`，
  而不是显示"精确"骗人。
- 同理：UDP 无法归因、短连接可能漏、内网地址不查归属地——都写进 README 与界面提示。

## 四、数据与测试纪律（血泪教训）

### 4.1 测试**绝对不能**写用户真实数据目录

- 事故：多个 agent 测试实例未带 `--datadir`，把用户真实数据 `%APPDATA%\NetWatcher\data\2026-10-31.json`
  覆盖了两次（133847 字节 → 6KB）。两次都靠"测试前恰好抓到完整原文"才恢复。
- **纪律**：
  1. 任何测试/截图/自检都传**绝对 `--datadir <临时目录>`**；
  2. 跑 GUI/daemon 前先 `Get-Process NetWatcher` 确认没有用户实例（或使用 `--mutex-tag`）；
  3. 测试后比对真实数据目录的 **size + mtime + SHA256** 零变化（`tools/qa/verify.ps1` 已内置守卫）；
  4. 结束进程只按自己记录的 **PID**，禁止 `Stop-Process -Name NetWatcher` 批量杀。

### 4.2 自动化验收（`tools/qa/verify.ps1`）

- 覆盖：编译 → `--selftest` 解析（管理员/EStats 结论/存储/GeoIP）→ `--daemon` 数据链路
  （逐 IP 合计 == 总量、samples ≤1440、connCount 合理、precision 诚实）→ 真实数据守卫 →（可选）GUI 冒烟。
- 基线对照：1.0 在 GUI 阶段 PASS=31 / FAIL=8（8 个 FAIL 全是真实缺陷：标签栏 0% 可见、列头 0% 可见、统计条被遮挡等），
  2.0 headless 回归 **PASS=27 / FAIL=0**。
- 教训：**先写可复跑的验收，再改代码**；"看起来能用"和"可验证能用"是两件事。

## 五、签名与分发

### 5.1 自签名 ≠ SmartScreen 放行

- 微软官方口径：自签名对 SmartScreen 的待遇**与未签名相同**。
- 自签名的价值：**本机 / 导入过证书的机器**不再显示"未知发布者"（Authenticode `Valid`）。
- SmartScreen「Windows 已保护你的电脑」主要由**Mark-of-the-Web（下载标记）**触发：
  - 本地编译产物默认没有 MotW，正常不会被拦；
  - 从网页/聊天软件下载的副本会带 MotW → `Unblock-File` 或右键属性"解除锁定"即可
    （`tools/fix-smartscreen.ps1` 一键处理，`install.ps1` 也会自动解除）。

### 5.2 商业证书：2026 年的现实

- **EV 不再"秒过" SmartScreen**（2024 起与 OV 一样走信誉积累），为 SmartScreen 买 EV 已无意义。
- 个人最低成本正规路径：**Certum 个人版云签名 ≈600 元/年**（自然人可办、无需营业执照、云 HSM）。
- 开源免费：**SignPath Foundation**；Certum 开源名额（需 OSS 资格）。
- **Azure Trusted Signing**（$9.99/月）Public Trust 地区**不含中国大陆**。
- 没有证书能"立刻让所有人不报警"：需要在固定发布者身份下持续签名 + 下载量积累；
  唯一彻底免费无提示的路径是 Microsoft Store（MSIX，商店重签名）。
- 详见 `tools/sign/README.md`（含价格、门槛、链接）。

### 5.3 签名工程约束

- **签名必须在编译之后**：`build.bat` 会覆盖 exe；用 `build-and-sign.bat` 一条命令完成。
- 自签名证书的私钥（`.pfx`）**绝不入库**（已在 `.gitignore`）；公钥 `.cer` 可分发。
- 别的机器要信任：把 `.cer` 导入 `Cert:\CurrentUser\Root` 与 `TrustedPublisher`（每台一次，无需管理员）。

## 六、关键决策（ADR 摘要）

| 编号 | 决策 | 理由 |
|---|---|---|
| ADR-01 | 坚持**零依赖单 exe**（系统自带 `csc.exe`，C# 5 / .NET Framework 4.8） | 双击即用，用户不装任何东西；与 1.0/v1 的项目精神一致 |
| ADR-02 | 数据按日 JSON + **原子写** + 分钟桶 | 可读、可回看、断电不坏；文件大小可控 |
| ADR-03 | 精确模式**诚实标注**，EStats 失败自动降级 | 1.0 的"假精确"是最大信任破坏 |
| ADR-04 | 安装到 `%LOCALAPPDATA%\Programs\NetWatcher` | 规避受限目录写盘问题；程序与仓库解耦；升级只需重跑安装脚本 |
| ADR-05 | 引擎与 UI **解耦** | UI/托盘异常不能影响数据采集 |
| ADR-06 | 单实例 + **二次启动唤出窗口** | 托盘可能不可见，必须留入口 |
| ADR-07 | 记录**所有远端 TCP 状态**，字节只对 ESTABLISHED | 贴近资源监视器口径，同时避免估算失真 |
| ADR-08 | 归属地联网查询 `Proxy = null` + 后台队列 + 缓存 | 本机系统代理不可用；解析不能阻塞采样 |
| ADR-09 | 签名：本机自签、分发另议 | 自签对 SmartScreen 无效；EV 无性价比；分发需 OV/SignPath |
| ADR-10 | 文档 + `verify.ps1` 入库 | 把"当时怎么想的、怎么验的"固化，降低后来者成本 |
| ADR-11 | 2.1 做**独立文件夹 + 改名 + 换安装位置**（`2.1/`、`Programs\NetWatcher2.1`、`Run\NetWatcher2.1`、`IP监控2.1.lnk`） | 用户要求"版本迭代"；与 2.0 并列交付、互不覆盖，2.0 保持可回退；exe 名不变以降低工具链改动面 |
| ADR-12 | 2.1 数据目录**继续用** `%APPDATA%\NetWatcher` | 历史连续，升级不迁移；代价是 2.0/2.1 不能同时运行（写进文档与锁的设计） |
| ADR-13 | 2.1 新增**数据写锁**，`--selftest` 改**只读** | 2.0 的"同目录多写者"和"自检写用户数据/改自启"是真实事故源；锁名带数据目录哈希，selftest 不抢锁 |
| ADR-14 | 2.0 文件在仓库里**冻结**，2.1 的脚本/文档全部新写（不共享文件） | 避免"改 2.0 影响已交付版本"；两份安装/卸载脚本各自只认自己的目录/自启值/快捷方式 |

## 七、给后来者的检查清单

接手/继续开发前，按顺序过一遍：

1. **能编译吗**：`cmd /c build.bat` → `bin\NetWatcher.exe`（约 109KB，签名后约 110KB）。
2. **改完签名了吗**：`build-and-sign.bat`（否则 exe 是未签名状态，本机仍可用）。
3. **数据能写吗**：用 `--selftest --datadir <绝对临时目录>`，看 `selftest.log` 是否生成。
4. **跑验收了吗**：`tools/qa/verify.ps1 -SkipGui -Seconds 45 -AuditRealData` 应 PASS=27。
5. **动过 UI 吗**：真机截图验收（四标签页、列头、数据非空），别只看代码。
6. **碰过安装/卸载吗**：install → 启动 → 数据写入 → uninstall（保留数据）→ 重装，全链路过一遍。
7. **碰过真实数据目录吗**：对比 size+mtime+SHA256 必须零变化。
8. **EStats 相关**：先管理员跑 `--selftest` 看 `EStats 结论:`，不要在"不可用"的机器上反复怀疑代码。

## 八、2.1 新增的坑与决策（2026-10-31）

> 这一节记录 IP监控2.1 相对 2.0 修掉的问题。每条都按「症状 → 根因 → 2.1 处理 → 如何验证」写。
> 对应代码在 `2.1/src/`；设计契约见 `docs/design-2.1.md` §5/§8；回归验收见 `2.1/tools/qa/`。

### 8.1 【P0】`--selftest` 会覆盖用户当天的真实数据

- **症状**：跑过一次 `NetWatcher.exe --selftest`（尤其是没带 `--datadir` 的）之后，
  当天的 `%APPDATA%\NetWatcher\data\<今天>.json` 变小/内容变成自检样本；
  用户在界面里看到"今天流量/连接记录少了一大截"。
- **根因**：2.0 的自检流程会走与正常监控相同的 `Store` 写入路径（创建并写当天 DayData），
  自检进程停在一个几乎为空的数据集上，落盘时就把真实当天数据覆盖了。
- **2.1 处理**：`--selftest` 改为**只读**——不 `SaveDay`、不创建/覆盖 `data\<今天>.json`、
  不写采样数据；只允许写 `selftest.log` 自身。
- **验证**：`--selftest --datadir <临时目录>` 前后对比该目录 `data\` 下文件不存在/内容不变；
  同时跑在真实目录的旧实例不应被影响。
- **教训**：**诊断功能必须是只读的**。凡是"检测/自检/修复"类入口，先问"它会不会写用户数据"。

### 8.2 【P0】`--selftest` 会篡改 HKCU 开机自启

- **症状**：用户明明在设置里关了开机自启，跑过一次自检后注册表里又出现 `Run\NetWatcher`；
  或用户开着的自启被自检删掉。表现为"自启设置自己变了"。
- **根因**：2.0 的自检把"写/删开机自启"当成一项健康检查真的执行了（写入一个测试值或调用删除），
  测试结束没有还原（或还原失败），于是用户的实际自启状态被改。
- **2.1 处理**：自检**只读检查** `HKCU\...\Run\NetWatcher2.1`（以及 2.0 的 `Run\NetWatcher`），
  只打印"存在/不存在、值内容"，绝不 `SetValue` / `DeleteValue`。
- **验证**：`--selftest` 前后用 `reg query` 对比 `Run\NetWatcher2.1` 与 `Run\NetWatcher`，内容零变化。
- **教训**：**自检/诊断不得改变系统状态**。要测写能力，写临时目录/临时键，并确保能还原。

### 8.3 【P0】同日重启后当天数据丢失

- **症状**：中午退出程序、下午再启动，当天上午的连接/流量从"按日统计/历史概览"里消失，
  `data\<今天>.json` 被重写成只剩重启后的数据。
- **根因**：2.0 启动时把"今天"当成内存里新建的空 DayData，没有先 `LoadDay(today)` 读回已有文件；
  第一次落盘就把文件覆盖成新数据集（跨日切日逻辑只保护"旧日"）。
- **2.1 处理**：启动时若 `data\<今天>.json` 存在，先读回并在此基础上继续累加；
  `Store.LoadDay` 对"今天"同样适用。
- **验证**：同一天跑 `--daemon 20 --datadir <临时目录>` → 记录数据 → 再跑 `--daemon 20` 同一目录
  → 检查数据是"两次累加"而不是"只剩第二次"。
- **教训**：**"当天"的持久化不是特例**；凡按日归档，就要覆盖"当天重启"这条路径。

### 8.4 【P0】同一数据目录被多个实例同时写

- **症状**（2.0 可能存在）：GUI 在跑时又用 `--daemon` 采集，或两个窗口（不同启动方式/不同 mutex-tag）
  指向同一个 `--datadir`，JSON 内容互相覆盖、原子替换偶发失败、数据忽多忽少。
- **根因**：2.0 只有"单实例"（同 exe 的命名 Mutex），它只防止"同一次启动开两个窗口"，
  **不是"数据目录写者"约束**；`--daemon` 和带 `--mutex-tag` 的实例可以绕过它。
- **2.1 处理**：新增**数据写锁** `NetWatcher2.1_DataLock_<MD5(数据目录绝对路径小写)>`：
  - GUI 与 `--daemon` 启动时都抢；抢不到时 daemon **退出码 2**、GUI 提示后退出；
  - `--selftest` 只读、不抢锁；`--mutex-tag` 只改单实例互斥量名，**不影响**写锁；
  - `Store` 的临时文件改为**唯一名**，即使出现历史残留/边缘并发也不会互相覆盖 `.tmp`。
- **验证**：同一 `--datadir` 先起 GUI（或长 `--daemon`），再起 `--daemon 5` → 退出码 2；
  再起第二个 GUI → 提示后退出；`--selftest --datadir` 同目录仍可正常跑完。
- **教训**：**"单实例"和"单写者"是两件事**；按资源（数据目录）加锁，而不是按程序名。
  **2.0 管不到**：2.1 的写锁前缀是 `NetWatcher2.1_`，与 2.0 的互不相通 → 2.0/2.1 不能同时运行，
  升级前必须先退出 2.0（已写进 README/用户手册/START-HERE）。

### 8.5 2.1 与 2.0 共用数据目录的边界（别在脚本里"顺手清理"）

- **症状**（如果照抄 2.0 安装脚本会踩）：2.1 的 `install.ps1` 若沿用 2.0 的"清理 1.0 遗留
  `NetWatcher.lnk`"逻辑，可能删到 2.0 的桌面快捷方式；`uninstall.ps1` 若按进程名批量杀
  `NetWatcher`，会把用户的 2.0 实例一起杀掉。
- **2.1 决定**：
  - 安装/卸载脚本**只认** `%LOCALAPPDATA%\Programs\NetWatcher2.1`、`Run\NetWatcher2.1`、`IP监控2.1.lnk`；
  - **不删除** 2.0 的 `IP监控.lnk`、不改 `Run\NetWatcher`、不碰 `Programs\NetWatcher`；
  - 卸载时结束进程**按可执行文件路径精确匹配**（安装副本或 2.1 仓库 bin），2.0 进程只跳过并提示；
  - `-DeleteData` 会二次警告"2.1 与 2.0 共用数据目录，2.0 历史也会删"；
  - 安装时**只读提示** 2.0 的自启项/运行实例，不替用户改 2.0。
- **验证**：静态审查脚本（本轮不真实执行）；真机验证时，安装/卸载前后记录 2.0 的
  `Run\NetWatcher` 值、`Programs\NetWatcher` 目录、`IP监控.lnk`、数据目录 size/mtime/SHA256，必须零变化。
- **教训**：多版本共存时，**"卸载干净"的边界只能是自己的命名空间**；跨版本收拾是各版本自己的事。

### 8.6 2.1 文档/脚本 2.1 化的"改名不彻底"风险

- **症状**：文档里残留"安装到 `Programs\NetWatcher`""桌面「IP监控」""`Run\NetWatcher`"，
  用户照着做会装错/查错；更糟的是脚本里残留 2.0 的路径导致"卸载时删了 2.0 的东西"。
- **处理**：本轮把 `README.md`、`CHANGELOG.md`、`docs/START-HERE.md`、`docs/design-2.1.md`、
  `用户手册.md`、`开发与维护指南.md`、`踩坑与决策记录.md`、`2.1-交接说明.md`、
  `tools/sign/README.md` 全部 2.1 化；安装/卸载脚本重写并做 Parser 校验 + UTF-8 BOM 检查。
- **自检方法**（改完文档/脚本后必做）：
  ```powershell
  # 找 2.0 专属表述（允许出现在"边界说明"里，其余都要改）
  Select-String -Path 2.1\*.ps1,2.1\*.md,2.1\docs\*.md,2.1\tools\sign\README.md `
    -Pattern 'Programs\\NetWatcher(?!2\.1)|IP监控\.lnk|Run\\NetWatcher\b|IP监控2\.0|2\.0\.2' | Select-Object Path,LineNumber,Line
  # 语法检查（.ps1）
  ```

- **教训**：改名类需求要**列清单 + 全局搜索 + 脚本语法校验**三件套，不要凭记忆逐个改。

### 8.7 PowerShell 读/写含点号的注册表值名要 `.'NetWatcher2.1'`

- **症状**：用 `$obj.NetWatcher2.1`、`$obj.PSObject.Properties.NetWatcher2.1` 之类写法取
  `HKCU\...\Run` 下的 `NetWatcher2.1` 值时报错/取不到；脚本"看起来访问了值名"实际访问失败，
  在回归里表现为注册表备份/恢复为空、误判"值不存在"。
- **根因**：PowerShell 属性访问语法把 `.` 当作成员访问分隔符，`NetWatcher2.1` 会被拆成
  `NetWatcher2` 的成员 `1`（或直接解析错误）。
- **处理**：
  - 取属性一律加引号：`$item.'NetWatcher2.1'`；或直接用 .NET API
    `[Microsoft.Win32.Registry]::CurrentUser.OpenSubKey(...).GetValue('NetWatcher2.1')`；
  - `reg query ... /v "NetWatcher2.1"`（带引号）；
  - 回归脚本 `regression-p1.ps1` 用 .NET Registry API 按完整值名读写备份/恢复（R3/R8/R11 验证）。
- **证据**：P1 回归的 `Run\NetWatcher2.1` 备份/恢复、R3/R8/R11 全 PASS；`tools/qa/README.md` 已记录。
- **教训**：注册表值名含点号（2.1 的 `NetWatcher2.1`）时，**属性名必须引号化或用 API**，别用裸属性访问。

### 8.8 csc 构建非确定性：同源码多次构建 SHA256 不同

- **症状**：同一份源码连续 `build.bat`，`bin\NetWatcher.exe` 大小相同（113,664 B）但 SHA256 每次都变，
  容易误判"构建不一致 / exe 被篡改 / 回归测的不是同一产物"。
- **根因**：`csc.exe` 把编译时间戳写进 PE 头（TimeDateStamp），链接时间不同 → 字节不同。
- **处理**：
  - **不要**用"跨构建 SHA256 相等"判断一致性；
  - 一致性判据用「**同一时刻**源 exe 与 `%TEMP%` 运行副本 SHA256 相等」（`verify.ps1` 的 `RUN_EXE`）；
  - 发布记录写**版本号 + 大小 + 签名状态**，哈希只作当次快照（本机 csc 未加 `/deterministic`）。
- **证据**：P0 验收 3 次构建 SHA 分别 `FC727DC9…`/`BD071CB7…`/`8D122D37…`（同源码）；
  P1 冻结 exe `F876F10B…`（16:31:07）与 verify 内部重建 `38DE950B…`/`710022EB…` 同为 113,664 B。
- **教训**：**构建产物哈希不是"源码内容指纹"**；跨构建比较哈希会得出错误结论。

### 8.9 GUI-GUI 数据目录冲突是 MessageBox（`#32770`），要按窗口类/标题找

- **症状**：想验证"第二个 GUI 抢不到数据写锁会提示"，但用进程主窗口/托盘去找不到提示框；
  或脚本按标题找不到窗口。
- **根因**：冲突提示是 **WinForms `MessageBox`**：顶层窗口 class=`#32770`、标题=`IP监控2.1`、
  `visible=True`，它不是主窗口、也不在托盘菜单里。
- **处理**：`regression-p1.ps1` 的 R10 用 `EnumWindows` 找 `class=#32770` + `title=IP监控2.1` +
  `IsWindowVisible`，同时断言 GUI A 仍存活；结束后按自己记录的 PID 结束 B、A。
- **证据**：R10 PASS：GUI B pid=19844 弹出 title=`IP监控2.1` class=`#32770` visible=True，GUI A 仍存活。
- **教训**：模态提示框用 Win32 class 检测，别用"进程有没有窗口"或标题精确匹配猜。

### 8.10 自启对账：install / `--autostart-on` 之后"顺手保存设置"不能把自启删掉

- **症状**（2.0 行为会踩）：用 `install.ps1` 或 `--autostart-on` 写了自启，但 `config.json` 里
  `AutoStart` 仍是 false；打开设置显示"未勾选"，用户一点保存就把已配置的自启删了。
- **根因**：自启的**真实状态在 HKCU 注册表**，`config.json` 只是缓存/副本，二者可能不一致。
- **处理（P1-5，已实现）**：`Program.Main` 启动时用 `Startup.IsEnabled()` 覆盖 `cfg.AutoStart`；
  设置窗口打开前再对账一次；保存时先写注册表、再用 `Startup.IsEnabled()` 回读校准。
  R11 验证：sentinel 写入 `Run\NetWatcher2.1` 后启动 GUI 8 秒再结束，sentinel 仍在且值不变。
- **证据**：静态检查 `S_P1_5` PASS；R11 PASS；2.0 的 `Run\NetWatcher` 全程未变。
- **教训**：**系统状态（注册表/文件）是权威，config 只是缓存**；读端与写端都要对账。

### 8.11 `--selftest` 覆盖数据的正确修法：存储测试挪到 `selftest-store\` 子目录

- **症状/根因**：见 8.1——2.0 自检走正常 `Store` 写入路径，把自检样本写进当天 `data\<今天>.json`。
- **处理（P0-2，已实现）**：自检的"原子写/读"测试改为写 `<datadir>\selftest-store\`
  （自建目录、用后删除），**不碰 `data\`**；注册表测试改用临时值名 `NetWatcher2.1_SelfTest_<PID>`。
- **证据**：R2 预置哨兵后 `--selftest`，`data\2026-10-31.json` SHA256/size/字段完全一致、
  `data\` 文件集合不变、`R2_STORE_TMPDIR_CLEAN` 显示 `selftest-store` 已清理。
- **教训**：自检要验证"写能力"，就在数据目录下开**独立临时子目录**测，绝不碰正式 `data\`；
  自检不是"完全不写"，而是"不写用户数据"（`selftest.log`/`geocache.json` 仍会写）。

### 8.12 csc 版本资源来自 `AssemblyInfo.cs`，不是 `build.bat`

- **症状**：以为 `build.bat` 里没写版本号，exe 就没有版本资源；想改版本时去翻 build 脚本。
- **根因**：Win32 版本资源（FileVersion/ProductVersion/ProductName/FileDescription）由
  C# `[assembly: AssemblyVersion(...)]` 等特性生成，本项目放在 `src/AssemblyInfo.cs`。
- **处理**：2.1 在 `src/AssemblyInfo.cs` 声明 `2.1.0.0` + `IP监控2.1 (NetWatcher)`；
  回归 R9 断言 `FileVersion=ProductVersion=2.1.0.0`；`verify.ps1` 也校验版本。
- **证据**：R9 PASS（2.1.0.0 / FileDescription=`IP监控2.1 · 网络连接监控`）。
- **教训**：**改版本只改 `AssemblyInfo.cs`**，并让文档/安装脚本/回归的版本号保持一致。
